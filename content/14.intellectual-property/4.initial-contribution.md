When an existing project migrates to the Eclipse Foundation, we refer to the existing code as the Eclipse open source project’s *initial contribution*. An initial contribution is basically the first set of [project code](/intellectual-property/project-content/) contributions to the new Eclipse project. An initial contribution typically takes the form of one or more entire existing source code repositories or some snapshot of an existing code base.

> **Warning:** All Eclipse open source project content must be kept in source code repositories that are managed by the Eclipse Infrastructure Team. Our current options are [GitLab](/project-resources-and-services/gitlab/) or [GitHub](/project-resources-and-services/github/).

We must complete the open source [project creation process](/starting-a-project/) before we move any existing source code repositories or create new ones. Following a successful [Creation Review](/releases-and-reviews/creation-reviews/), the EMO will initiate the [provisioning](/starting-a-project/provisioning/) process. It is during the provisioning process that we activate project committers, move/create source code repositories, and create other project resources.

The short version of the process is this:

- Complete the [proposal process](/starting-a-project/project-proposal/) and [creation review](/releases-and-reviews/creation-reviews/);

- Project team and EMO works with Eclipse Infrastructure Team to set up source code repositories;

- The EMO initiates the intellectual property review of the default branch of all repositories; and

- The EMO IP Team will inform the EMO when the reviews are complete.

> **Tip:** The [Moving an Existing Repository](/intellectual-property/project-content/#moving-an-existing-repository) section describes options available for moving an existing repository.
