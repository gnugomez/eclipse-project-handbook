The charts that are displayed in on the project page are generated nightly based on commit data from the project’s source code repositories. The data includes commits that have been merged into any branch (other than the `gh_pages` branch); it excludes merge commits and any commit that has been authored by a bot. It makes no consideration of where commits come from: a commit is a commit. Whether a commit comes via a pull request, or is pushed directly by a committer, it is counted as one commit.

> **Note:** Note that care should be taken to not draw conclusions from any chart in isolation. The manner in which committers engage on a project can have a significant impact on the commit count. It is, for example, entirely reasonable for a project to employ an incremental change strategy that integrates the CI. That is, a project team may (and some of our projects do) implement a strategy of creating many relatively small commits for each issue, pausing to get validation from the CI before proceeding. It’s not reasonable or fair to compare the number of commits against a project that may use another strategy.
